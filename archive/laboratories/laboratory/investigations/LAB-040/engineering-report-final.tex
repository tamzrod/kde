\section{Investigation 1: Alerting Labels Issue}

\subsection{Issue Overview}

\begin{tabular}{|l|p{10cm}|}
    \hline
    \rowcolor{light}
    \textbf{Grafana Issue} & \textbf{\href{https://github.com/grafana/grafana/issues/116074}{\#116074}} \\
    \textbf{Title} & Alerting: Manually Set labels not present in namespace \\
    \textbf{Created} & January 9, 2026 \\
    \textbf{Labels} & \texttt{type/bug}, \texttt{area/alerting}, \texttt{area/backend} \\
    \hline
\end{tabular}

\subsection{Problem Description}

When setting a custom label manually in an alert rule (e.g., \code{environment: production}), this label does not appear in the \code{\$labels} namespace that is interpolated into notification messages.

\begin{context}
    \textbf{Expected Behavior:} The manually set label should be present in the \code{\$labels} namespace when using template syntax like \code{\{\{\$labels\}\}} in notification messages.
\end{context}

\subsection{Code Flow Analysis}

The investigation traced the label expansion through the following components:

\begin{enumerate}
    \item \textbf{Alert Evaluation} $\rightarrow$ \code{newState()} in \code{state/state.go}
    \item \textbf{Label Expansion} $\rightarrow$ \code{expandAnnotationsAndLabels()} in \code{state/cache.go}
    \item \textbf{Template Expansion} $\rightarrow$ \code{Expand()} in \code{state/template/template.go}
    \item \textbf{Alert Conversion} $\rightarrow$ \code{StateToPostableAlert()} in \code{state/compat.go}
\end{enumerate}

\subsection{Root Cause}

\begin{keyfinding}
    Found in \code{pkg/services/ngalert/state/cache.go} line 154: The template data used for expanding alert rule labels only contains \code{extraLabels} and \code{resultLabels}, not the manually set rule labels themselves.
\end{keyfinding}

\begin{minted}[bgcolor=light, fontsize=\small]{go}
// Current code - template data only has extraLabels + resultLabels
templateData := template.NewData(mergeLabels(extraLabels, resultLabels), result)

// When expanding rule labels, $labels doesn't include rule.Labels
labels, _ := expand(ctx, log, alertRule.Title, alertRule.Labels, templateData, ...)
\end{minted}

\section{Investigation 2: Histogram Log Axis Issue}

\subsection{Issue Overview}

\begin{tabular}{|l|p{10cm}|}
    \hline
    \rowcolor{light}
    \textbf{Grafana Issue} & \textbf{\href{https://github.com/grafana/grafana/issues/13027}{\#13027}} \\
    \textbf{Title} & Log axis limits ``auto'' doesn't work on histogram \\
    \textbf{Created} & August 24, 2018 (7+ years ago) \\
    \textbf{Labels} & \texttt{type/bug}, \texttt{area/panel/graph}, \texttt{help wanted} \\
    \hline
\end{tabular}

\begin{important}
    This is one of the oldest open bugs in the Grafana repository, confirmed present across versions 4.6.3 through 6.5.3 with 12+ comments confirming bug persistence.
\end{important}

\subsection{Problem Description}

When setting up a histogram with a logarithmic scale on ``auto'', the Y-axis maximum limit gets stuck at 1k (100 in code), regardless of the actual data values.

\begin{context}
    \textbf{Workaround Available:} Setting explicit Y-axis maximum values manually works correctly. The issue is specifically with the ``auto'' limit calculation for log scales.
\end{context}

\subsection{Critical Finding: Hardcoded Y-Axis}

\begin{keyfinding}
    Found in \code{public/app/plugins/panel/histogram/Histogram.tsx} line 152: The histogram panel hardcodes the Y-axis scale distribution to \code{ScaleDistribution.Linear}.
\end{keyfinding}

\begin{minted}[bgcolor=light, fontsize=\small]{typescript}
builder.addScale({
    scaleKey: 'y', // counts
    isTime: false,
    distribution: ScaleDistribution.Linear,  // HARDCODED!
    orientation: ScaleOrientation.Vertical,
    direction: ScaleDirection.Up,
    softMin: 0,
});
\end{minted}

\subsection{X-Axis vs Y-Axis Comparison}

\begin{tabular}{p{3cm}ccp{4cm}}
    \toprule
    \textbf{Aspect} & \textbf{X-Axis} & \textbf{Y-Axis} & \textbf{Status} \\
    \midrule
    Scale Distribution & Configurable & Hardcoded Linear & $\times$ \\
    Log Scale Support & Yes & No & $\times$ \\
    Range Function & Custom for log & Default linear & $\times$ \\
    Auto-scaling & Works & Broken for log & $\times$ \\
    \bottomrule
\end{tabular}

\begin{important}
    Note: The X-axis properly supports log scale based on bucket size differences, but the Y-axis does not share this capability.
\end{important}
