## Research Questions Addressed

### 1. What should be considered the canonical command?

**Decision**: The canonical command is the authoritative, versioned identifier stored in the Alias Registry.

| Property | Value |
|----------|-------|
| Versioned | Yes (semantic versioning) |
| Stable | Yes (never deprecated, only superseded) |
| Used in scripts | Yes |
| Used in documentation | Yes (primary) |
| Defined in | `/runtime/aliases/registry.json` |

**Canonical Command Rules**:
1. Each canonical command has exactly one authoritative definition
2. Canonical commands are immutable once published
3. Breaking changes require new canonical command with migration path

### 2. Should every canonical command support aliases?

**Decision**: No. Not every canonical command requires aliases.

| Scenario | Alias Required? | Rationale |
|----------|-----------------|-----------|
| User-facing operations | Yes | Usability benefit |
| Internal ECU operations | No | Technical precision required |
| State machine states | No | Single authoritative name |
| Low-level APIs | No | Developer-focused |
| High-level workflows | Yes | Human interaction |

**Criteria for Alias Eligibility**:
- Command is user-facing (not internal)
- Command appears in documentation
- Command is used in natural language interaction
- Alias improves usability without ambiguity

### 3. Can multiple aliases exist?

**Decision**: Yes, with categorization and governance.

| Category | Max Aliases | Example |
|----------|------------|---------|
| Friendly | Unlimited | "pre-flight", "check", "health" |
| Professional | Unlimited | "system-check", "runtime-status" |
| Operational | Unlimited | "go", "launch", "mission-ready" |
| Deprecated | Unlimited | "old-command" (with warnings) |

**Multi-Alias Rules**:
1. All aliases in same category must be unique
2. Cross-category aliases may exist but must not conflict
3. Priority order: Canonical > Operational > Professional > Friendly

### 4. Should aliases be categorized?

**Decision**: Yes. Categories provide governance structure and discoverability.

#### Category Definitions

| Category | Purpose | Target Users | Tone |
|----------|---------|-------------|------|
| **Friendly** | New users, casual interaction | Beginners | Informal |
| **Professional** | Engineering communication | Engineers | Technical |
| **Operational** | Mission-oriented workflow | Operators | Directive |
| **Deprecated** | Compatibility | Migrating users | Warning |

#### Category Examples

```
Canonical: runtime preflight

├── Friendly
│   ├── pre-flight
│   ├── check
│   └── health
│
├── Professional
│   ├── system-check
│   └── runtime-status
│
├── Operational
│   ├── go
│   ├── launch
│   └── mission-ready
│
└── Deprecated
    ├── flight-check    (deprecated 2025-01)
    └── ready          (deprecated 2025-06, use "go")
```

### 5. How should deprecated aliases be handled?

**Decision**: Deprecated aliases follow a defined lifecycle with warnings.

#### Deprecation Lifecycle

```
┌─────────────────────────────────────────────────────────────┐
│ DEPRECATION LIFECYCLE                                       │
└─────────────────────────────────────────────────────────────┘

    ACTIVE          DEPRECATED        REMOVED
        │                │               │
        │                ▼               │
        │    ┌───────────────────┐       │
        │    │ Warning emitted   │       │
        │    │ Suggest canonical │       │
        │    └───────────────────┘       │
        │                │               │
        │                │ (12 months)   │
        │                ▼               │
        │    ┌───────────────────┐       │
        │    │ Alias removed    │       │
        │    │ from registry    │       │
        │    └───────────────────┘       │
        │                                │
        └───────────────────────────────►│
```

#### Deprecation Rules

| Rule | Description |
|------|-------------|
| Warning period | Minimum 12 months |
| Warning content | "Deprecated: use [canonical] instead" |
| Migration support | Provide canonical equivalent |
| Documentation | Marked as DEPRECATED in docs |
| Tracking | Log deprecation in registry |

### 6. Should aliases be discoverable at runtime?

**Decision**: Yes, with categorized discovery.

#### Discovery Mechanism

```python
# Runtime discovery API
class AliasRegistry:
    def discover_all(self) -> List[Alias]:
        """Return all aliases"""
    
    def discover_by_category(self, category: Category) -> List[Alias]:
        """Return aliases in specific category"""
    
    def discover_friendly(self) -> List[Alias]:
        """Return friendly aliases for new users"""
    
    def resolve(self, alias: str) -> Optional[Canonical]:
        """Resolve alias to canonical command"""
```

#### Discovery Endpoints

| Endpoint | Returns | Use Case |
|----------|---------|----------|
| `GET /aliases` | All aliases | Admin tooling |
| `GET /aliases?category=friendly` | Friendly aliases | Onboarding |
| `GET /aliases?category=operational` | Operational aliases | Mission control |
| `GET /aliases/resolve?alias=go` | Canonical command | Execution |

### 7. Should aliases appear in documentation or only canonical names?

**Decision**: Both, with clear hierarchy.

#### Documentation Guidelines

| Document Type | Canonical First | Alias Examples | Notes |
|--------------|----------------|----------------|-------|
| Technical Reference | ✅ Always | ❌ No | Precision required |
| User Guide | ✅ Primary | ✅ Secondary | Usability focus |
| Quick Reference | ✅ Primary | ✅ Listed | Fast lookup |
| API Documentation | ✅ Always | ❌ No | Developer focus |
| Onboarding | ✅ Primary | ✅ Highlighted | Learning aid |

#### Format Examples

```
Technical Reference:
  runtime preflight

User Guide:
  runtime preflight (also: pre-flight, go, check)

Quick Reference Card:
  ┌──────────────────┬──────────────────┐
  │ Canonical        │ Aliases          │
  ├──────────────────┼──────────────────┤
  │ runtime preflight│ go, check, health│
  └──────────────────┴──────────────────┘
```

### 8. How should alias conflicts be resolved?

**Decision**: Conflicts follow priority hierarchy and namespace rules.

#### Conflict Types

| Conflict Type | Resolution |
|--------------|------------|
| Alias matches canonical | Reject alias registration |
| Alias duplicates alias | Reject (same category only) |
| Cross-category collision | Allow with warning |
| Operational overrides friendly | Friendly takes precedence for users |
| Namespace collision | Namespace-qualified alias |

#### Conflict Resolution Algorithm

```
1. Check if alias equals any canonical command
   → REJECT if equal

2. Check if alias exists in same category
   → REJECT if duplicate

3. Check cross-category conflicts
   → WARN if conflict exists

4. Apply namespace if collision detected
   → QUALIFY with namespace prefix
```

### Lifecycle States

```
┌─────────────────────────────────────────────────────────────┐

└─────────────────────────────────────────────────────────────┘

    ┌──────────┐
    │ PROPOSED │  (submitted for approval)

         │ approved

    ┌──────────┐
    │ ACTIVE   │◄─────────┐  (in use)

    ┌──────────────┐        │
    │ DEPRECATED  │────────┘
```

| From | To | Trigger | Authority |
|------|----|---------|-----------|
| Proposed | Active | Governance approval | Human |
| Active | Deprecated | Deprecation notice | Human |
| Deprecated | Active | Undeprecation | Human |
| Deprecated | Removed | Time period | Auto (after 12 months) |

## Naming Convention

### Format Rules

| Rule | Format | Example |
|------|--------|---------|
| **Canonical** | `{namespace} {command}` | `runtime preflight` |
| **Operational** | `{action}` or `{action}-{modifier}` | `go`, `launch-investigation` |
| **Professional** | `{noun}-{verb}` or `{system}-{check}` | `system-check`, `runtime-status` |
| **Friendly** | `{simple-action}` or `{phrase}` | `check`, `health`, `ready` |

### Naming Constraints

| Constraint | Rule | Example |
|------------|------|---------|
| Max length | 50 characters | `runtime preflight` (17 chars) ✓ |
| No spaces in alias | Use hyphens | `system-check` ✓, `system check` ✗ |
| Lowercase only | All aliases lowercase | `GO` ✗, `go` ✓ |
| No reserved words | System keywords | `help`, `exit` reserved |
| Unique within category | No duplicates | Only one "go" in Operational |

### Namespace Convention

```
{namespace}/{alias}

Example:
  mission/go        (mission namespace)
  lab/preflight     (lab namespace)
  runtime/preflight (runtime namespace)
```

## Conflict Resolution

### Resolution Priority

| Priority | Type | Resolution |
|----------|------|------------|
| 1 | Exact match canonical | Execute canonical |
| 2 | Unique alias | Execute with translation |
| 3 | Multiple aliases | User disambiguation prompt |
| 4 | Deprecated alias | Warning + execute |
| 5 | Unknown command | Error with suggestions |

### Disambiguation Algorithm

```python
def resolve_command(input: str) -> Resolution:
    # 1. Check if canonical
    if input in canonical_commands:
        return Resolution(canonical=input, alias_used=None)
    
    # 2. Check aliases
    matches = alias_registry.find(input)
    
    if len(matches) == 0:
        return Resolution(error="Unknown command")
    
    if len(matches) == 1:
        return Resolution(
            canonical=matches[0].canonical,
            alias_used=input
        )
    
    if len(matches) > 1:
        # Multiple matches - disambiguate
        return Resolution(
            error="Ambiguous command",
            suggestions=matches
        )
```
