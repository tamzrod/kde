## 3. Issue 2: ECU Routing Failure

### 3.1 What Should Happen

```
User: "Investigate [topic]"
         │
         ▼
    ECU checks: Is this KDE-related?
         │
         ├── YES → Route to appropriate engine
         │
         └── NO → Block with error:
                   "This topic is not KDE-related.
                    KDE runtime should only be used for KDE-specific investigations."
```

### 3.2 What Actually Happened

```
User: "Investigate monolith vs microservices"
         │
         ▼
    ECU: (No scope check)
         │
         ▼
    Investigation created anyway ❌
```

### 3.3 Evidence - No Scope Validation

| Component | Has Scope Check? | Evidence |
|-----------|-----------------|----------|
| `ecu/__init__.py` | ❌ No | No `scope`, `topic`, or `kde_related` methods |

| `ecu/bootstrap/__init__.py` | ❌ No | No scope validation |
| File Boundary Guard | ❌ No | Only path validation, not topic |

### 3.4 Root Cause

**The ECU has no scope validation mechanism.**

The ECU only:
- ✅ Validates investigation naming patterns
- ✅ Enforces Five Core Principles
- ❌ **Does NOT validate if investigation topic is KDE-related**

### 3.5 What Needs to Be Added

A scope validation component that:
1. Checks if investigation topic is KDE-related
2. Defines "KDE-related" criteria
3. Blocks non-KDE investigations
