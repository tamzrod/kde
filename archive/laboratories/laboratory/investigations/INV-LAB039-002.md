## Executive Summary

This investigation examined Grafana issue #13027, one of the oldest open bugs in the repository (~7 years). The issue reports that when using log scale on a histogram panel, the "auto" limits for the axis don't work correctly, causing the maximum value to be stuck at a default value (1k/100).

**Root Cause Identified**: The issue stems from two related problems:
1. The histogram panel's Y-axis scale is hardcoded to `ScaleDistribution.Linear`, ignoring user configurations
2. The scale builder's fallback logic can trigger inappropriately when log scale ranges have edge cases

---

## Issue Description

**Original Report** (from 2018):
- **Grafana Version**: v4.6.3 (confirmed present in v5.2.3, v6.2.5, v6.5.3)
- **Datasource**: InfluxDB
- **Problem**: When setting up a histogram with a logarithmic scale on "auto", the Y max limit gets stuck at 1k
- **Expected**: The graph should scale automatically to show the maximum value
- **Actual**: Y max limit stuck at 1k, works correctly with linear scale

**Screenshots Description** (from issue):
- Linear scale histogram: Y-axis auto-scales correctly showing max values
- Log scale histogram: Y max stuck at 1k regardless of actual data
- Manual Y max setting: Graph renders correctly when explicit max is set

### Critical Finding: Hardcoded Y-Axis Distribution

**Location**: `public/app/plugins/panel/histogram/Histogram.tsx` (lines 149-156)

```typescript
builder.addScale({
  scaleKey: 'y', // counts
  isTime: false,
  distribution: ScaleDistribution.Linear,  // ⚠️ HARDCODED!
  orientation: ScaleOrientation.Vertical,
  direction: ScaleDirection.Up,
  softMin: 0,
});
```

**Problem**: The histogram panel hardcodes the Y-axis scale to `Linear`, completely ignoring any user-configured scale distribution.

### Secondary Finding: Fallback Guard Logic

**Location**: `packages/grafana-ui/src/components/uPlot/config/UPlotScaleBuilder.ts` (lines 259-263)

```typescript
// guard against invalid y ranges
if (minMax[0]! >= minMax[1]!) {
  minMax[0] = scale.distr === DISTR_MAP[ScaleDistribution.Log] ? 1 : 0;
  minMax[1] = 100;  // ⚠️ Default fallback
}
```

**Problem**: This fallback triggers when `min >= max` (invalid range). For log scales with edge case data (e.g., [1, 1] or very small ranges), this can result in the default [1, 100] range being used.

### X-Axis Log Scale Configuration

**Location**: `public/app/plugins/panel/histogram/Histogram.tsx` (lines 111-147)

```typescript
builder.addScale({
  scaleKey: 'x',
  distribution: isOrdinalX
    ? ScaleDistribution.Ordinal
    : useLogScale
      ? ScaleDistribution.Log  // ✓ Properly configured for log
      : ScaleDistribution.Linear,
  log: 2,
  range: useLogScale
    ? (u, wantedMin, wantedMax) => {
        return uPlot.rangeLog(wantedMin, (wantedMax ?? 1) * bucketFactor, 2, true);
      }
    : ...,
});
```

The X-axis properly supports log scale based on bucket size differences, but the Y-axis does not.

## Recommended Fixes

### Fix 1: Support Y-Axis Scale Distribution in Histogram Panel

Modify `public/app/plugins/panel/histogram/Histogram.tsx` to accept and use scale distribution from field config for the Y-axis:

```typescript
builder.addScale({
  scaleKey: 'y',
  isTime: false,
  distribution: customConfig.scaleDistribution?.type ?? ScaleDistribution.Linear,
  log: customConfig.scaleDistribution?.log ?? 2,
  orientation: ScaleOrientation.Vertical,
  direction: ScaleDirection.Up,
  softMin: 0,
});
```

### Fix 2: Improve Fallback Logic (Optional Enhancement)

Review and potentially improve the fallback guard logic in `UPlotScaleBuilder.ts` to handle edge cases better, perhaps by:
- Checking for null/undefined data values
- Using a more context-aware default range
