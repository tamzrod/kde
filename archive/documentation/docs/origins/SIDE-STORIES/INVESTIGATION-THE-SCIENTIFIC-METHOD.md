## Investigation Question

How did the author independently arrive at investigation-driven engineering principles, and how did the Scientific Method later explain patterns already observed through practical engineering experience?

---

## The Engineering Journey

### Phase 1: Software Projects Become Complex

The author's software projects grew increasingly complex. Traditional approaches—agile, waterfall, object-oriented design—explained how to structure code but not how to discover what needed to be built.

### Phase 2: Agentic Coding Emerges

AI-assisted development made implementation faster. But faster implementation of the wrong thing is still the wrong thing. Capability without direction.

### Phase 3: The Search for Process

The author searched for a repeatable engineering process. Something that could be applied consistently across different problems. A methodology for discovery, not just implementation.

### Phase 4: Experiments Converge

Multiple experiments slowly converged toward investigation-driven engineering. Observations, hypotheses, evidence, iteration. The pattern emerged from practice, not theory.

### Phase 5: The Scientific Method Recognition

One day, reading about the Scientific Method, the author realized: "We've been rediscovering it without recognizing it."

---

## The Key Insight

**NOT**: "We should use science in software engineering."

**YES**: "We've been practicing science all along. The Scientific Method explains what we've been doing and gives it a name."

---

## Engineering Questions

1. How do engineers discover truth rather than merely produce software?
2. Does software engineering require an explicit discovery methodology in addition to an implementation methodology?
3. Can agentic coding generate implementations while still lacking a reliable method for discovering architectural truth?
