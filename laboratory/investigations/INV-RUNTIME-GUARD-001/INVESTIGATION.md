## Objective

Implement **ACTIVE ENFORCEMENT** of file boundary rules during runtime:

1. **When "start engine" is invoked** → Runtime initializes with enforcement active
2. **When user instructs to write a file** → Runtime checks if within permitted boundaries
3. **If outside `/laboratory/` (and not exempt)** → Flag as violation, request override
4. **Only proceed if human approves** → Log all decisions

---

## Problem Statement

The user expects:

```
User says: "start engine"
         ↓
Runtime starts with Laboratory Rules actively enforced
         ↓
User says: "write a file at /workspace/project/kde/new-file.md"
         ↓
Runtime: "⚠️ VIOLATION: This is outside /laboratory/
         Override? [Yes/No]"
         ↓
Human approves or blocks
         ↓
Action proceeds or is rejected ✅
```

## Investigation Tasks

### Task 1: Design Active Enforcement Mechanism

Design a `FileBoundaryGuard` that:
1. Intercepts all file write operations
2. Checks if target is within permitted boundaries
3. Flags violations and requests human approval
4. Logs all decisions

### Task 2: Define Permitted Boundaries

| Path | Status | Reason |
|------|--------|--------|
| `/laboratory/**` | ✅ ALLOWED | Laboratory Rules apply |
| `/runtime/logs/**` | ✅ ALLOWED | Runtime logs (exempt) |
| All other `/workspace/project/kde/**` | ⚠️ VIOLATION | Requires human approval |

### Task 3: Design Violation Response

When a violation is detected:
1. Present violation to human with details
2. Request override approval
3. Log decision
4. Execute or block based on decision
