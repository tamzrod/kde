Issue Summary

Log axis "auto" limits don't work on histogram panel. Y-axis max stuck at 100 regardless of actual data values.

Confirmed affected: v4.6.3 → current
Finding 01

Histogram Y-Axis Ignores User Configuration

Severity: Medium Confidence: High

The histogram panel hardcodes Y-axis scale to Linear, completely ignoring user-configured log scale settings.

Histogram.tsx:149-156 
builder.addScale({
  scaleKey: 'y',
  isTime: false,
  distribution: ScaleDistribution.Linear,  // HARDCODED
  orientation: ScaleOrientation.Vertical,
  direction: ScaleDirection.Up,
  softMin: 0,
});

Impact: Users cannot use log scale effectively on histogram Y-axis. Manual Y-max workaround available but defeats auto-scaling purpose.

Finding 02

Scale Builder Fallback Triggers Incorrectly

Severity: Low Confidence: Medium

Fallback logic sets Y-max to 100 when range calculation produces invalid values for log scale data.

UPlotScaleBuilder.ts:259-263 
if (minMax[0]! >= minMax[1]!) {
  minMax[0] = scale.distr === Log ? 1 : 0;
  minMax[1] = 100;  // Explains the 1k stuck max
}
User selects log Y-axis → Scale hardcoded to Linear → Auto-range fails for log data → Fallback: [1, 100]
Comparison

X-Axis vs Y-Axis Implementation

Component X-Axis Y-Axis
Distribution Configurable ✗ Hardcoded Linear
Log Support ✓ ✗
Auto-scaling ✓ ✗
Custom Range ✓ ✗

The X-axis already supports log scale properly—the Y-axis simply wasn't updated to match.

Solution

Proposed Fix

Histogram.tsx 
// Read scale distribution from field config
const yScaleDistribution = 
  firstFieldConfig.scaleDistribution?.type ?? ScaleDistribution.Linear;

builder.addScale({
  scaleKey: 'y',
  isTime: false,
  distribution: yScaleDistribution,
  log: yScaleDistribution === ScaleDistribution.Log ? 2 : undefined,
  orientation: ScaleOrientation.Vertical,
  direction: ScaleDirection.Up,
  softMin: yScaleDistribution === ScaleDistribution.Log ? null : 0,
});
