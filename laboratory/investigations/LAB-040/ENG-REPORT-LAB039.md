## Issue Summary

Log axis "auto" limits don't work on histogram panel. Y-axis max stuck at 100 regardless of actual data.

**Confirmed affected**: v4.6.3 → current (7+ years)

# Investigation Card 01

## Histogram Y-Axis Ignores User Configuration

**Severity**: Medium  
**Confidence**: High  
**Files**: 2

The histogram panel hardcodes Y-axis scale to `Linear`, ignoring user-configured log scale settings.

### Evidence

```typescript:public/app/plugins/panel/histogram/Histogram.tsx:149-156
builder.addScale({
  scaleKey: 'y',
  isTime: false,
  distribution: ScaleDistribution.Linear,  // ← HARDCODED
  orientation: ScaleOrientation.Vertical,
  direction: ScaleDirection.Up,
  softMin: 0,
});
```

### Impact

Users cannot use log scale effectively on histogram Y-axis. Manual Y-max workaround available but defeats auto-scaling purpose.

# Investigation Card 02

## Scale Builder Fallback Triggers Incorrectly

**Severity**: Low  
**Confidence**: Medium  
**Files**: 1

Fallback logic sets Y-max to 100 when range calculation produces invalid values.

### Evidence

```typescript:packages/grafana-ui/src/components/uPlot/config/UPlotScaleBuilder.ts:259-263
if (minMax[0]! >= minMax[1]!) {
  minMax[0] = scale.distr === Log ? 1 : 0;
  minMax[1] = 100;  // ← Explains the 1k stuck max
}
```

### Root Cause Chain

```
User selects log Y-axis
    ↓
Scale hardcoded to Linear
    ↓
Auto-range calculation fails for log data
    ↓
Fallback triggers with default [1, 100]
```

# Proposed Fix

```typescript
// Read scale distribution from field config
const yScaleDistribution = 
  firstFieldConfig.scaleDistribution?.type ?? ScaleDistribution.Linear;

builder.addScale({
  scaleKey: 'y',
  isTime: false,
  distribution: yScaleDistribution,
  log: yScaleDistribution === ScaleDistribution.Log ? 2 : undefined,
  orientation: ScaleOrientation.Vertical,
  direction: ScaleDirection.Up,
  softMin: yScaleDistribution === ScaleDistribution.Log ? null : 0,
});
```
