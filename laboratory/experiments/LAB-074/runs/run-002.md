## Gap Identified

**The Problem**:
The runtime `SkillLoader` only reads from `registry.json`. It does NOT scan `.agents/skills/` directory for skill files.

**Evidence**:
- Skill file exists with proper YAML front matter
- Triggers are correctly defined: `investigation`, `experiment`, `start engine`, `preflight check`
- But the loader's `select_skills_for_task()` returns nothing for these triggers

**Why it fails**:
1. `SkillLoader.__init__` creates `SkillRegistry()`
2. `SkillRegistry.__init__` reads `registry.json` only
3. `.agents/skills/` is never scanned
4. Skills in that directory are invisible to the runtime

---

## Conclusion

**Root Cause Identified**: The runtime has no mechanism to discover skills in `.agents/skills/` directory.

**Solution Options**:
1. **Option A**: Add directory scanning to `SkillLoader`
2. **Option B**: Auto-register discovered skills to `registry.json`
3. **Option C**: Both (hybrid approach)

**Recommendation**: Implement Option C - hybrid approach that:
1. Scans `.agents/skills/` on startup
2. Merges discovered skills with registry
3. Supports both registered and discovered skills
